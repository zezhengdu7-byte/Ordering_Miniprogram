# 炭火里 · 微信原生点餐 Demo

同一个微信小程序内体验顾客菜单、购物车、订单，以及商家分区管理、菜品编辑和订单处理。原生 WXML / WXSS / TypeScript；无会员、充值和余额功能。独立编写，参考 orderFood-wxCloud 的功能组织，没有复制其源码或图片。

## 打开预览

在微信开发者工具中导入本项目根目录（有 `project.config.json` 的目录），使用已关联的微信云开发环境 `cloud1-d0g5igvuk85096f8a`。已提交编译后的 `.js`，首次打开不需要安装依赖。当前已配置测试号“点单实验室”的 AppID；真机预览、上传和微信能力需使用该小程序管理员或已授权开发者的微信登录。云端身份认证、菜单、桌码会话、订单及数据库已部署，当前授权微信可进入商家端；配置与权限说明见 [身份认证](docs/authentication.md) 与 [云端部署记录](docs/cloud-deployment.md)。若基础库下载失败，请在“设置 → 项目设置 → 本地设置”选择可用基础库并编译。

模拟器默认显示顾客菜单，底部只有“点餐 / 订单”。扫描正式桌码后加入本桌用餐会话；未扫码时只能浏览菜单，不能提交订单。长按菜单店名进入门店身份验证页，只有云端确认的店主或员工可进入商家工作台。

## 开发

```sh
npm install
npm run build
npm run watch
npm test
```

TypeScript 与编译产物放在同一目录，开发工具直接使用 JavaScript。修改 `.ts` 后运行 build/watch；编译产物应随源码一起保留。不要同时编辑 `.ts` 和 `.js`。

## 建议体验顺序

1. 顾客菜单包含肉串烧烤、海鲜烤鱼、蔬菜素串、锡纸系列、家常热炒、凉菜小吃、主食搭配、酒水饮料八个分区。纸质菜单录入 52 道菜（花生、毛豆分别展示），保留原有两款饮品，共 54 款；菜品配图为 AI 生成。升级自动更新默认菜单，保留自建菜品、历史订单及店铺设置。纸单的 5 串起点保留为菜品说明，当前加购仍按单串操作。
2. 可选辣度菜品从零点加号时弹出辣度选择，确认后加入；之后沿用购物车中该菜品最后一行口味，减到零再加会重新选择。饮料直接加购，旁边减号可减至零。点菜品图片可另选辣度；购物车仍按口味分行，可精确修改数量、备注并提交云端订单。
3. 订单写入云端并同步到商家订单页。当前付款仍是模拟操作，弹窗明确提示不会扣款，也不会写入真实支付流水。
4. 商家工作台包含菜品、分区、订单、店铺设置、桌台与桌码、打印机六个入口。开发工具可先本地预览；真实身份接入按 [身份认证配置](docs/authentication.md)。
5. 切回顾客菜单验证修改；已加入购物车的停售菜品必须移除后才能提交。
6. 商家“菜品管理”可搜索、按分区和售卖状态筛选、新增、编辑、上下架、设置售罄和删除菜品；“分区管理”为独立页面，可新增、改名、排序、上下架和删除空分区。分区下架会隐藏区内菜品，并阻止旧购物车继续下单；重新上架保留菜品各自的状态。
7. 商家“订单管理”可搜索订单、筛选状态、接单、完成出餐、取消待接单或制作中订单、查看厨房小票预览。取消保留历史订单及模拟付款标记，不涉及真实退款；已结束订单不可取消。
8. 店铺设置修改店名、欢迎词和营业状态；休息时顾客不能提交订单。桌台管理支持新增、编辑、删除和设置本机体验桌，未完成订单的桌台不能改名或删除。
9. 打印机管理可保存设备名称、演示编号、联数和自动打印偏好，查看测试小票；未接硬件，不发送任务。

## 本版边界

- 菜单、分区、店铺设置、桌台、用餐会话和订单已写入微信云开发；顾客购物车保存在当前设备，尚未接入跨设备共享加购。
- 所有数据库集合禁止客户端直接读写；顾客和商家操作均经云函数校验可信微信 OPENID、APPID、角色、会话成员资格及版本。
- 正式版桌码已经接入；固定桌码跨用餐复用，每次结束用餐后创建新会话，旧会话不能继续下单。
- 微信支付、退款和硬件云打印尚未接入。模拟付款不会扣款，打印机设置只保存偏好。
- 没有会员、充值、余额、多人分账、优惠券或多门店切换。
- 菜品图片保存在微信云存储；菜品价格以整数分保存，提交时由云端重新计算，历史订单保留菜品及价格快照。

多门店方案及预算见 [部署与费用](docs/deployment-and-cost.md)。图片生成提示词见 [图片记录](docs/image-prompts.md)。

## 商家端参考

参考 [orderFood-wxCloud](https://github.com/yangxiaohan168/orderFood-wxCloud) 的工作台功能分组与独立页面结构，保留本项目烧烤店视觉，独立实现 WXML/WXSS/TypeScript。没有会员、充值、余额和密码管理；权限使用可信微信身份校验。桌台管理可批量生成 A01–A30 固定桌码并保存到相册。打印配置只保存偏好，未绑定真实设备。今日概览排除取消订单，模拟付款金额单独标识。

[业务数据库设计](docs/database-model.md)包含字段、关系、索引、权限、并发及状态流转。类型见 `database/model.ts`，索引见 `database/collections.json`。13 个集合、索引和禁止客户端直读写的安全规则已部署；业务读写由 `restaurant` 与 `table-service` 云函数完成。无多门店与会员功能。
