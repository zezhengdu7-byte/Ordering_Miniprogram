# 炭火里 · 微信点餐小程序

面向烧烤门店的微信原生点餐小程序，包含顾客扫码点餐和商家经营管理两端，覆盖扫码入座、选菜加购、订单处理、代客点单和整桌结算。前端使用 WXML、WXSS 和 TypeScript，后端使用微信云开发。

**当前状态：正在门店实地测试中。** 菜单、桌码、用餐会话、订单和商家身份认证已接入云端，持续根据现场使用情况完善功能。真实微信支付、退款和硬件打印尚未接入。

## 客户端功能

### 扫码入座

- 扫描固定桌码，校验桌台并创建或加入本桌用餐会话，页面显示已确认桌号。
- 未选桌或桌号校验中可浏览菜单，不能加购和下单；页面提供扫码入口。
- 同桌顾客分别扫码后加入同一次用餐，可各自提交订单和加单，账单按整桌汇总。
- 用餐结束后旧会话失效，下一批顾客扫码开启新会话，旧会话不能继续下单。

### 菜单与购物车

- 按肉串烧烤、海鲜烤鱼、蔬菜素串、锡纸系列、家常热炒、凉菜小吃、主食搭配、酒水饮料等分区浏览菜品，查看图片、价格和说明。
- 支持快捷加减、数量调整和购物车管理；相同菜品按辣度分行，同款同口味累加。
- 可选辣度包括不辣、微辣、中辣、特辣，每次打开口味弹窗默认不辣；无需辣度的菜品直接加购。
- 支持起点数量规则，例如标注 5 串起点的菜品首次加入 5 串，减到起点以下时移除。
- 菜品或分区下架、菜品售罄后阻止新增和下单，购物车中的相关菜品仍可移除。
- 定期同步云端菜单与桌台状态，门店休息时停止接收新订单。

### 用餐人数与餐具费用

- 下单前确认用餐人数、餐具和纸巾数量，费用在购物车及订单合计中展示。
- 餐具、纸巾可调整数量或减至零，单价使用门店配置。
- 费用按本次用餐记录，后续加单不重复收取，收费状态及金额由服务端校验。

### 订单与结算

- 提交云端订单，支持继续加单，查看本人订单的菜品、数量、口味、备注、金额和状态。
- 按待接单、制作中、已完成等状态查看订单，订单页显示期间每 5 秒刷新。
- 本人待接单且未结算的订单可修改原有菜品数量和备注，或取消；接单后顾客不能再修改或取消。
- 查看整桌未结账单，汇总同桌顾客的多笔订单；存在未完成订单时不能结算。
- 客户端目前保留模拟结算入口，确认框明确提示不会扣款；结清后结束本次用餐，旧会话不能继续下单。

## 商家端功能

### 身份认证与经营概览

- 长按菜单店名进入身份验证页，通过微信身份和云端门店角色校验后进入工作台。
- 展示今日接待桌数、当日已结算金额、待接单数、制作中订单数，以及菜品、分区和桌台数量。
- 接待桌数按用餐会话去重，同桌加单不重复计数，翻台后的新用餐单独计数。
- 已结算金额按结清日期统计，支持跨日用餐，取消订单不计入有效消费。
- 提供菜品、分区、订单、桌台、桌码、店铺设置和打印机管理入口，可切回顾客点餐页面。

### 菜品与分区管理

- 菜品支持搜索、按分区和售卖状态筛选、新增、编辑、上下架、设置售罄及删除。
- 管理菜品名称、价格、图片、说明、所属分区和口味选项等资料。
- 分区支持新增、改名、排序、上下架和删除空分区，非空分区不能直接删除。
- 分区下架后隐藏区内菜品并阻止继续下单，重新上架保留菜品原有售卖状态。
- 菜单调整同步到顾客端，已提交订单保留当时的菜品与价格快照。

### 订单处理

- 查看全店订单，按待接单、制作中、已完成、已取消或全部状态筛选，按桌号、菜品及备注搜索。
- 接单、完成出餐，取消待接单或制作中的未结算订单；取消前需确认，历史记录保留。
- 修改待接单或制作中、尚未结算的订单，调整原有菜品数量、辣度及备注，按规则重算金额。
- 查看厨房小票预览，订单状态与版本由云端校验，避免重复处理或覆盖其他操作。

### 桌台管理与代客点单

- 查看桌台总数、在用桌数、当前有效订单数、待接单数和消费合计。
- 按桌展示当前用餐的订单、状态、金额和来源，区分顾客扫码与商家代下。
- 进入本桌订单页处理本次用餐的订单，查看消费合计、未完成订单和未结金额。
- 选择桌台后代客点单：空桌自动开桌，已有用餐则加入当前会话，复用菜单、餐具确认及下单流程。
- 切换代客点单桌台时，如购物车非空，会提示确认并清空，避免将菜品带入另一桌。
- 本桌订单全部完成后，商家确认顾客已结清，记录结算并结束用餐；云端校验会话和未结金额，金额变化时要求刷新重试。

### 桌码管理

- 新增桌台并生成固定正式版桌码，支持批量生成或补齐 A01–A30 桌码。
- 查看、预览桌码并保存到相册，便于打印和放置在桌面。
- 重复生成复用已有桌码，固定桌码可跨多次用餐使用。
- 启用或停用桌码：停用阻止新的扫码入座，进行中的用餐不受影响；重新启用后原码继续可用。
- 删除已结束用餐的桌台后旧码失效，同名新建桌台使用新的桌码。

### 店铺与打印设置

- 设置店名、欢迎词、营业状态、餐具单价和纸巾单价。
- 门店休息时阻止提交新订单。
- 保存打印设备名称、编号、联数及自动打印偏好，提供测试小票预览；尚未连接硬件，不发送实际打印任务。

## 实地测试范围与当前限制

- 当前面向单门店使用，顾客与商家操作通过微信云函数完成。
- 同桌订单及账单在云端汇总，购物车保存在各自设备，尚未支持跨设备共享购物车。
- 微信支付、退款尚未接入。商家确认结清用于记录已核实的结算状态，不代表小程序发起或核验了真实收款；客户端模拟结算不会扣款或产生真实支付流水。
- 硬件云打印尚未接入，目前只提供设置保存及小票预览。
- 暂无会员、充值、余额、优惠券、多人分账和多门店切换功能。
- 本地测试覆盖业务逻辑，门店网络、真机并发及现场使用效果仍在实地测试中持续验证。

## 技术与数据

- 前端：微信原生小程序，WXML / WXSS / TypeScript，编译后的 JavaScript 随源码保留。
- 后端：微信云开发数据库、云函数和云存储，菜品图片保存在云存储。
- 云函数：`identity` 处理身份认证，`restaurant` 处理菜单、配置和订单，`table-service` 处理桌码与用餐会话，`provision` 负责受限的初始化操作。
- 权限：数据库禁止客户端直接读写，云函数校验可信微信身份、AppID、角色、用餐会话及版本。
- 金额：以整数分保存，下单时由服务端核价，历史订单保留菜品及价格快照。

数据模型见 [业务数据库设计](docs/database-model.md)，类型定义位于 `database/model.ts`，集合与索引定义位于 `database/collections.json`。

## 本地开发

在微信开发者工具中导入包含 `project.config.json` 的项目根目录。真机预览、代码上传及微信能力调用需使用管理员或已授权开发者的微信账号，并配置对应云开发环境，详见 [身份认证](docs/authentication.md)。

```sh
npm install
npm run build
npm run watch
npm test
```

TypeScript 与编译产物位于同一目录，开发者工具直接使用 JavaScript。修改 `.ts` 后运行 `npm run build` 或 `npm run watch`，将编译产物与源码一起提交，避免同时手动修改 `.ts` 和 `.js`。

`npm test` 执行小程序编译、数据库类型检查及业务测试，涵盖身份权限、菜单与购物车、下单与改单、餐具费用、桌台与桌码、代客点单、整桌结算和工作台统计。
